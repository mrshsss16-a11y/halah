## 🔴 معطّلات الإطلاق (لا يمكن الإطلاق قبلها)

### B1 — بوت واتساب متوقف الآن
**الدليل:** آخر رد من البوت 2026‑07‑23 12:56. بعده ٣ رسائل واردة (14:37, 15:12, 15:19)
**بلا أي رد**. السبب: `WHATSAPP_TOKEN` الحالي توكن اختبار مؤقت ينتهي خلال ساعات.

هذا **جوهر المنتج** — إطلاق ببوت ميت يعني عميل يراسل ولا أحد يرد.

**الحل (يتطلب إجراءً منك في Meta):**
1. Business Settings → System Users → أنشئ System User
2. امنحه: `whatsapp_business_messaging` + `whatsapp_business_management`
3. Generate Token → **بدون تاريخ انتهاء** → سلّمه ليُحفظ في `WHATSAPP_TOKEN`
4. التحقق: أرسل رسالة، ثم أعد الإرسال بعد ٢٤ ساعة — يجب أن ينجح الاثنان

الدليل التفصيلي: `functions/_lib/integrations/WHATSAPP_TOKEN_GUIDE.md`

### B2 — الرقم التجريبي لا يصلح للإطلاق
الرقم الحالي `+1 555 152 2369` رقم اختبار من Meta (أمريكي، صالح ٩٠ يوماً، لا يستقبل من عملاء حقيقيين).

**الحل:** ربط رقم أورا الحقيقي عبر **Coexistence** (يبقى تطبيق واتساب بزنس شغالاً + API معاً)
من WhatsApp Manager → Phone Numbers → Add phone number. هذا يفعّل أيضاً ميزة "الرد اليدوي
يُسكت البوت ساعتين" المبرمجة أصلاً.

### B3 — مراجعة صدق المحتوى المعروض
قاعدة الصدق في المشروع تمنع عرض أرقام غير حقيقية. قبل الإطلاق: مراجعة بصرية لصفحة الهبوط
والداشبورد للتأكد أن كل رقم أو ادعاء إما حقيقي أو صياغة نوعية.
`/api/stats` يعيد الآن أرقاماً حقيقية (كلها 0 اليوم — وهذا صادق).

**قرار مطلوب منك:** ما الذي يُعرض مكان الأرقام الصفرية عند الإطلاق؟ (اقتراح: صياغة نوعية
بدل عدّادات فارغة، أو إخفاء العدّادات حتى تتراكم بيانات حقيقية.)

## 🟠 قبل استقبال أول عميل يدفع (خلال أسبوع من الإطلاق)

### P1 — مراجعة سقوف التكلفة (تحقق، لا إصلاح عاجل)
الفحص أظهر أن الحماية **موجودة فعلاً**، لكن بآليات مختلفة لا بـ `checkAndConsume`:

| Endpoint | الحماية القائمة |
|---|---|
| `support` (عام) | rate limit ٢٠ طلب/دقيقة لكل IP ✅ |
| `whatsapp/webhook` | توقيع إلزامي + بوابات التصعيد: ٣ رسائل غير محلولة/ساعة ← تصعيد بلا استدعاء AI، ثم صمت ساعتين ✅ |
| `scan`, `store/sandbox` | حارسان لكل منهما ✅ |
| `trendyol/qa` | ٣ حراس ✅ |
| `admin/*` | `requireAdmin` ✅ |

**المطلوب:** مراقبة الاستهلاك الفعلي أول أسبوع (لوحة Cloudflare AI) ومعايرة الأرقام على
سلوك حقيقي، بدل تخمينها مسبقاً. ليس معطّل إطلاق.

### P2 — توحيد رقم التذكرة
عمود `ticket_code` في قاعدة البيانات + حساب مستقل في `webhook.js` = الرقم المُرسل للعميل
قد لا يطابق المخزّن. يجب اعتماد مصدر واحد.

### P3 — تفعيل تذكير المواعيد
`functions/api/cron/reminders.js` موجود لكن **لا cron trigger** في `wrangler.toml`.
العميل يحجز استشارة ولا يصله تذكير.

```toml
[triggers]
crons = ["*/30 * * * *"]
```

### P4 — مراقبة الأخطاء
حالياً `console.error` فقط — لا تنبيه. عطل مثل توقف البوت (B1) بقي أياماً دون ملاحظة.
الحد الأدنى: فحص دوري لـ `/api/health` + تنبيه عند فشله.

## لماذا "إطلاق محدود" وليس إطلاقاً واسعاً

- بوت خدمة العملاء لم يعمل بعد بحمل حقيقي — سلوك النموذج تحت ضغط رسائل متزامنة غير مُختبر.
- سقوف التكلفة موجودة لكن أرقامها مُخمَّنة، لم تُعايَر على استخدام حقيقي (P1).
- لا مراقبة (P4) — عطل صامت قد يمر أياماً، كما حدث فعلاً مع B1 (البوت متوقف منذ ١١ يوماً
  دون أن يلاحظ أحد).

٥‑١٠ عملاء أوائل يكشفون هذا بأمان. التوسّع بعد أسبوع من التشغيل النظيف.
