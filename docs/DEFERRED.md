## بوابة القرار — يُصلَح الآن أم يُؤجَّل؟

**لا يُؤجَّل** أي خطأ ينطبق عليه واحد من هذي الخمسة:

| # | المعيار | لماذا |
|---|---|---|
| **Q1** | يُنتج مخرجاً **خاطئاً أو مفبركاً** يصل عميلاً | يكسر قاعدة الصدق (`AGENT.md` §١١) — أثمن ما بُني |
| **Q2** | يكسر **عزل المتاجر** أو يسرّب بيانات بينها | خسارة ثقة غير قابلة للاسترجاع |
| **Q3** | يكشف **سراً أو بيانات شخصية** (PII) | مخاطرة قانونية وأمنية |
| **Q4** | يقدر يُسقط **خدمة حية** أو يوقف الرد على عملاء | أثر تشغيلي مباشر |
| **Q5** | **يحجب الإطلاق** فعلياً | يعطّل كل ما بعده |

**كل ما عدا ذلك يُؤجَّل** — ويُسجَّل هنا بمحفّزه.

**قاعدة المدير:** لا يُصلَح بند مؤجَّل خارج محفّزه إلا بقرار صريح. "شفته وأنا مارّ فأصلحته"
هو بالضبط النمط اللي يفكك الخطة ويحوّل يوم عمل إلى ثلاثة.

## قواعد الدفتر

1. **كل بند مؤجَّل يحمل محفّزاً.** بلا محفّز = دَين صامت، لا تأجيل مُدار.
2. **المحفّز يُفحص عند كل معلم بالخطة** — قبل بدء أي أسبوع جديد، اقرأ هذا الملف واسأل: هل انطبق محفّز؟
3. **بند يستوفي Q1–Q5 لاحقاً يخرج فوراً** من التأجيل، ولو كان مؤجَّلاً بالأمس. الظروف تتغير: مسار داخلي يصير عاماً، وأدمن واحد يصير اثنين.
4. **لا إضافة بند هنا بلا تسجيله بـ`PROBLEMS.md` أولاً** — هذا دفتر جدولة، لا سجل مشاكل موازٍ.
5. **المراجعة إلزامية عند:** كل إطلاق · دخول أي شخص جديد للفريق · أي تغيير بنطاق المستخدمين (أورا → تجار).
