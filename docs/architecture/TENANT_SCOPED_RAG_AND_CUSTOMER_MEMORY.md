# تصميم RAG وذاكرة العميل المعزولين

## الهدف

يجب أن يجيب وكيل المتجر من بيانات متجره فقط، وأن يتذكر العميل داخل المتجر نفسه عبر الزيارات والقنوات المصرح بها. لا توجد ذاكرة عامة تحتوي حقائق متجر، ولا يسمح للنموذج بأن يحول تشابه النصوص إلى صلاحية وصول.

> **قاعدة أمان:** الهوية والنطاق يحددان البيانات قبل الاسترجاع؛ النموذج لا يملك صلاحية اختيار المتجر أو العميل.

## طبقات المعرفة

| الطبقة        | النطاق                             | الاستخدام                              | القاعدة                                                 |
| ------------- | ---------------------------------- | -------------------------------------- | ------------------------------------------------------- |
| أسلوب هالة    | عام                                | اللهجة السعودية البيضاء وأسلوب الصياغة | لا يحتوي سياسة أو سعر أو حقيقة متجر                     |
| سياسة المتجر  | منظمة + اتصال متجر                 | الشحن، الإرجاع، الدفع، أوقات الدعم     | لا تستخدم خارج `organization_id` و`store_connection_id` |
| منتجات المتجر | منظمة + اتصال متجر                 | المواصفات والمخزون والوصف              | لا تعتمد إلا إذا كان المصدر فعالاً                      |
| ذاكرة العميل  | منظمة + اتصال متجر + عميل          | التفضيلات والسياق والموافقة            | لا تنتقل إلى متجر آخر ولا إلى عميل آخر                  |
| سجل المحادثة  | منظمة + اتصال متجر + عميل + محادثة | استكمال الحوار                         | يُحمّل بعد إثبات هوية العميل ونطاقه                     |
| السلة         | منظمة + اتصال متجر + عميل + سلة    | تذكّر المنتجات والحالة                 | لا تستخدم للإرسال دون consent وpolicy                   |

## تدفق الرد الآمن

1. يحدد النظام المتجر من جلسة الواجهة أو توقيع قناة سلة/واتساب، وليس من نص العميل.
2. يحدد هوية العميل من معرف المتجر الخارجي أو contact hash أو visitor key hash. لا يعتمد على اسم أو رقم مكتوب داخل الرسالة.
3. يتحقق من أن `customer_profile` تابع للمنظمة والاتصال نفسيهما، وأن حالته ليست `blocked` أو `deleted`.
4. يسترجع من Vectorize المرشحين باستخدام namespace وmetadata الخاصة بالمتجر. يمكن أن تكون مكتبة الأسلوب عامة، لكن لا تُقبل نتائج policy أو product بلا نطاق متجر.
5. يتحقق من كل مرشح في D1: `status = active`، ونافذة الفعالية صحيحة، والنطاق مطابق، والمصدر غير منتهي.
6. يحمّل آخر رسائل المحادثة وملخصها وحقائق الذاكرة الصريحة فقط. الحقائق المستنتجة لا تُستخدم في قرار حساس إلا بعد تأكيد العميل.
7. يمرر للنموذج سياقاً منظماً مع تعليمات: استخدم المصادر فقط، لا تخترع سياسة أو سعراً أو مخزوناً، وإذا غاب الدليل فقل إنك تحتاج التحقق أو صعّد للموظف.
8. يمرر الناتج عبر بوابة ادعاءات قبل الإرسال؛ تُرفض الإجابة إذا تضمنت حقيقة غير موجودة في المصادر أو خلطاً في اسم المتجر أو بيانات متجر آخر.
9. يُحفظ الرد مع `organization_id` و`store_connection_id` و`conversation_id` و`customer_profile_id`، ويُستخدم مفتاح idempotency لمنع التكرار.

## الذاكرة المستمرة

يستمر العميل في المحادثة عبر الأيام عندما يعود بنفس هوية المتجر الخارجية أو بنفس معرف الزيارة الموثق. عند عدم وجود هوية موثوقة، يبدأ النظام جلسة مجهولة جديدة ولا يخمن أنها الشخص نفسه. ربط الهوية يجب أن يحدث عبر قناة يثبتها المتجر أو عبر موافقة العميل، وليس عبر تشابه الاسم أو النص.

تُخزن الرسائل والملخصات وحقائق العميل مشفرة مع رقم إصدار المفتاح. تحفظ الذاكرة طويلة الأمد فقط ما يحتاجه المنتج: تفضيل صريح، نية، موافقة، سياق دعم، أو سياق سلة. لا تُحفظ استنتاجات حساسة بلا تأكيد. يستطيع العميل سحب الموافقة أو طلب حذف الذاكرة، وعندها تُلغى الحقائق وتُغلق إمكانية التحميل المستقبلية.

## عزل قاعدة البيانات والفهرس

المصدر الجديد يستخدم D1 كمصدر الحقيقة. كل جدول خاص بالمعرفة والمحادثة والعميل يحمل نطاقاً صريحاً، وكل استعلام يتطلب المنظمة والاتصال بالمتجر. Vectorize يسترجع مرشحين فقط ولا يُعامل كحاجز أمني وحيد. يمكن استخدام فهرس مشترك مع namespace وmetadata filter صارمين لتقليل التكلفة، أو فهرس مستقل للعملاء ذوي الحساسية العالية، لكن D1 يبقى مرجع التحقق في الحالتين.

أي نتيجة بلا `organization_id` و`store_connection_id` لا تُقبل إذا كانت من نوع policy أو product أو faq. الاستثناء الوحيد هو أسلوب هالة العام، ويجب أن يبقى خالياً من حقائق المتاجر.

## السلة

يربط حدث السلة المتروكة `external_cart_id` بالمتجر والعميل بعد التحقق من webhook وتوقيعه. تحفظ لقطة السلة مشفرة، وتُحدّث idempotently. لا يرسل النظام تذكيراً لمجرد وجود سجل؛ يفحص الموافقة، suppression، سياسة المتجر، حالة السلة، وحدود المحاولات. إذا عاد العميل للمحادثة، يمكن عرض سياق السلة له بعد إثبات نفس العميل ونفس المتجر فقط.

## سيناريوهات منع الخلط

| الاختبار                             | النتيجة المطلوبة                                                           |
| ------------------------------------ | -------------------------------------------------------------------------- |
| عميل متجر A يسأل عن شحن متجر B       | لا تظهر أي سياسة من B؛ يطلب النظام تفاصيل متجر A أو يصعّد                  |
| نفس العميل يعود بعد يومين            | تُحمّل محادثته وذاكرته من متجره نفسه إذا كانت الهوية موثقة والموافقة سارية |
| عميلان لهما الاسم نفسه               | يبقيهما النظام هويتين منفصلتين ما لم يوجد معرف موثوق مشترك                 |
| عميل يحاول تغيير المتجر داخل الرسالة | لا يتغير النطاق؛ المتجر يؤخذ من القناة الموثقة                             |
| نتيجة Vectorize بلا مصدر D1 فعال     | تُرفض ولا تصل للنموذج كحقيقة                                               |
| طلب حذف الذاكرة                      | تُلغى الذاكرة وتمنع إعادة تحميلها، مع سجل تدقيق غير حساس                   |
| webhook مكرر للسلة                   | لا ينشئ سياقاً أو إرسالاً مكرراً                                           |

## ما أُضيف في المصدر الجديد

أضيفت migration `0016_tenant_scoped_customer_memory.sql` وتشمل `knowledge_items` و`knowledge_vectors` و`customer_profiles` و`conversation_threads` و`conversation_messages` و`customer_memory_facts` و`customer_cart_context`، مع مفاتيح وفهارس نطاقية وقيود تمنع جعل معرفة المتجر عامة بالخطأ.

هذه migration تؤسس التخزين فقط. لا تعتبر الذاكرة أو RAG جاهزين حتى تُضاف خدمات D1، ومرشح Vectorize، وتشفير الرسائل، ومسارات المحادثة، وعمليات الحذف وسحب الموافقة، واختبارات العزل والهلوسة.

## ما لن نفعله

لن نضع كل العملاء في prompt واحد، ولن نستخدم الذاكرة من KV كمصدر حقيقة، ولن نسمح للنموذج باختيار `organization_id` من كلام العميل، ولن نستورد رسائل WhatsApp الخام إلى مكتبة الأسلوب تلقائياً، ولن نخلط ردود هالة العامة بسياسات متجر العميل.
