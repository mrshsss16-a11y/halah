# بوابة جاهزية staging لهالة

**الحالة الحالية:** هذا المستند خطة تحقق فقط. لا يعني وجود بيئة staging، ولا يجيز إنشاء موارد Cloudflare أو ربط سلة أو زد أو مزود بريد أو واتساب.

## الهدف والنطاق

تُفصل staging عن development والإنتاج فصلاً كاملاً حتى يختبر فريق هالة مسارات SaaS ببيانات تركيبية وموارد مستقلة. لا تستخدم هذه البيئة متجر عميل أو بيانات عميل أو مفتاحاً أو token من الإنتاج. لا تمر أي عملية ربط خارجي أو callback أو webhook حي إلا بعد موافقة صريحة على الإجراء المحدد ومراجعة هذا المستند.

| البوابة     | شرط النجاح                                          | الدليل المطلوب                         | الحالة الآن                 |
| ----------- | --------------------------------------------------- | -------------------------------------- | --------------------------- |
| المصدر      | فرع `main` نظيف ومراجع                              | commit محدد و`git status --short` فارغ | متحقق محلياً قبل كل دفعة    |
| الجودة      | unit + integration + build dry-run + E2E محلي ناجحة | مخرجات أو CI موثّق                     | متحقق محلياً؛ CI غير مستعاد |
| فصل الموارد | D1/KV/Workers staging مستقلة تماماً                 | أسماء ومعرّفات غير إنتاجية             | غير منشأ                    |
| الأسرار     | أسرار staging فقط خارج Git                          | قائمة bindings بلا قيم                 | غير مهيأ                    |
| البيانات    | fixtures تركيبية وغير قابلة لتحديد عميل             | مراجعة fixtures                        | مطلوب عند تجهيز staging     |
| الاستعادة   | export واختبار restore موثق                         | تقرير تمرين restore                    | غير منفذ                    |
| التكاملات   | متجر demo ومفاتيح اختبار فقط                        | موافقة صريحة ونطاقات محددة             | محظور حالياً                |

## مصفوفة إعدادات غير حساسة

لا تضع القيم أو المفاتيح في هذا الملف أو في `wrangler.jsonc`. يجري إعدادها من لوحة أسرار البيئة أو آلية نشر موثقة بعد الموافقة.

| المفتاح أو المورد           | staging                         | الضابط                                                                  |
| --------------------------- | ------------------------------- | ----------------------------------------------------------------------- |
| `ENVIRONMENT`               | `staging`                       | قيمة صريحة تمنع مسارات development-only                                 |
| `APP_VERSION`               | إصدار commit قابل للتتبع        | لا يُنشر `latest` غير قابل للتدقيق                                      |
| D1                          | قاعدة مستقلة                    | لا تشارك production أو development                                      |
| KV rate limit               | namespace مستقل                 | لا يخزن tokens أو بيانات عملاء                                          |
| `CREDENTIAL_ENCRYPTION_KEY` | مفتاح AES-256 خاص بـstaging     | secret خارج Git؛ key version موثق؛ غير مطلوب قبل token exchange المعتمد |
| `SALLA_WEBHOOK_SECRET`      | سر staging خاص بالمتجر التجريبي | لا يضبط قبل موافقة تسجيل webhook                                        |
| OAuth client credentials    | بيانات تطبيق اختبار فقط         | لا تضبط قبل موافقة OAuth وتسجيل callback                                |

## تسلسل نشر staging المقترح

1. تثبيت commit مرشح ومراجعة الفروقات، ثم تشغيل `pnpm check` و`pnpm build` و`pnpm --filter @hala/hala-edge test:e2e` على المصدر نفسه.
2. إنشاء موارد staging منفصلة **بعد موافقة صريحة**، مع least-privilege وبيانات تركيبية فقط.
3. تطبيق migrations من `0001` إلى آخر migration على D1 staging الفارغة، ثم إثبات الجدول `_cf_migrations` وقبول health check.
4. نشر Worker staging فقط، والتحقق من cookies الآمنة وCSP وCSRF وعزل المنظمة وسجل التدقيق من دون مزود خارجي.
5. تشغيل E2E وaccessibility وRed Team على نطاق staging، وتسجيل النتائج والعيوب المحلولة.
6. لا تبدأ OAuth أو webhook أو متجر demo إلا بقرار منفصل يذكر الموفر وبيئة الاختبار والنطاق والمورد الدقيق.

## خطة النسخ والاستعادة

| الإجراء          | الحد الأدنى قبل production                                    | ما يجب ألا يدخل النسخة                                     |
| ---------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| تصدير D1 staging | export مشفر ومحدود الوصول مع وقت وتوقيع مسؤول                 | credentials ciphertext خارج مفتاحها، أو أي بيانات عميل حية |
| اختبار الاستعادة | استعادة export إلى D1 اختبار مستقلة ثم فحص migrations وhealth | لا تستخدم D1 production كمكان اختبار                       |
| KV               | توثيق أن KV rate-limit/cache وغير authoritative               | لا تعتمد عليه لاسترجاع هوية أو policy أو credentials       |
| السجل            | حفظ metadata اللازمة للتدقيق وفق مدة احتفاظ معلنة             | لا تسجل body webhook أو token أو كلمة مرور                 |

## حواجز تمنع الانتقال إلى demo أو pilot

يظل الانتقال محظوراً إلى أن تكتمل الدعوات عبر مزود بريد معتمد، والتحقق من البريد أو reset، وتحديث Miniflare/Vitest المدعوم لإزالة تحذير compatibility، وCI فعلي، وE2E مع accessibility، وتمرین backup/restore، ونموذج observability، ومراجعة Red Team. كما يظل OAuth وwebhook الحيان وتسجيل تطبيق سلة أو زد وإرسال واتساب خارج نطاق هذا المستند ويتطلبان موافقات مستقلة.
