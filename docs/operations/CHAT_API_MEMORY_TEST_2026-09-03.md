# نتيجة اختبار API ومحادثة halah.aura.sa

- التاريخ: 2026-09-03.
- تم فتح واجهة المساعد العامة في `https://halah.aura.sa/`.
- أُرسل سؤال تجريبي غير حساس: `وش تسوي هالة بالضبط؟`
- عاد رد FAQ متوافق مع سجل `hala_faq` عن خدمات هالة.
- أُرسل سؤال متابعة: `وش قلت لك قبل شوي؟`
- أعاد المساعد مضمون الرد السابق بشكل صحيح داخل نفس فتح الصفحة؛ هذا يثبت ذاكرة محادثة قصيرة داخل الجلسة الحالية.
- أُعيد تحميل الصفحة. اختفت الرسائل السابقة وعادت النافذة إلى التحية الابتدائية؛ لا يوجد دليل على استمرار ذاكرة الزائر المجهول بعد reload.
- فحص أسماء التخزين في المتصفح أظهر `localStorage` و`sessionStorage` فارغين، واسم cookie الظاهر `g_state` فقط؛ لا يظهر معرف محادثة دائم للزائر المجهول في المتصفح.
- النطاق الحالي يعرض رابط `كمّل المحادثة على واتساب` بعد الرد.
- لم تُرسل أي رسالة إلى WhatsApp، ولم يُستخدم حساب أو بيانات عميل.

الاستنتاج: API القديم يملك استرجاعاً/سياقاً قصير الأمد داخل جلسة الصفحة، لكنه لا يثبت ذاكرة عميل مستمرة عبر الأيام أو بعد إعادة التحميل. الذاكرة المطلوبة يجب تنفيذها في المصدر الجديد مع معرف عميل موثوق، conversation_id دائم، وموافقة حفظ الذاكرة.

- استدعاء مباشر لـ`POST /api/support` برسالة متابعة منفردة أعاد نفس جواب FAQ؛ هذا لا يثبت ذاكرة خادم، لأن عقد الواجهة يرسل مصفوفة `messages` كاملة مع كل طلب، كما أن الرد قد يكون من FAQ/النموذج.
- عند السؤال عن سياسة شحن وإرجاع لمتجر غير محدد ومن دون سياسة، صعّد المساعد إلى فريق هالة بدلاً من اختراع سياسة. هذه نقطة إيجابية، لكنها لا تثبت عزل بيانات متجر بين عميلين لأن API العام لا يستقبل نطاق متجر موثقاً.
- لم يتم فتح رابط WhatsApp أو إرسال أي رسالة خارجية.
