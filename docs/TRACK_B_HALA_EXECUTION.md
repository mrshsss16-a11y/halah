**تصحيح مهم:** الافتراض الأصلي هنا ("٦ مسارات بلا حصة") كان منقولاً من `AGENT.md`

| `admin/aura_whatsapp.js` | معفى عمداً (`UNMETERED_MERCHANT_IDS` بـ`meter.js:25`) — استثناء موثّق، لا ثغرة |
| `whatsapp/webhook.js` | **مُقاس فعلاً** (`checkAndConsumeMonthly` سطر ٨٧) — الجزء الوحيد الناقص أدناه |
| `image.js` | ✅ أُغلق 2026-09-06 (هذا الأسبوع، مبكراً عن جدوله) |

**العمل الفعلي المتبقي — بند واحد، لا ستة:**

`webhook.js:87` يلف `checkAndConsumeMonthly` بـ`.catch(() => ({ ok: true }))`.
عطل مؤقت بـD1 أو KV ⇒ الرسالة **تمر بلا حساب** بدل الفشل الآمن (fail-open، عكس S1).

**هذا ليس إصلاحاً آلياً — قرار تجاري يحتاج مسار د:**
- **fail-closed:** عطل قاعدة بيانات مؤقت = توقف رد البوت لكل التجار فوراً (توفر أقل، دقة حصة أعلى)
- **fail-open (الوضع الحالي):** البوت يستمر بالرد أثناء العطل، برسائل غير محسوبة مؤقتاً (توفر أعلى، دقة حصة أقل)

**اقتراحي (للنقاش لا للتنفيذ الفوري):** fail-open مع **تسجيل الحدث** بدل الصمت
الكامل — يحافظ على التوفر، ويعطي رؤية لاحقة بحجم "الفجوة" بدل عمى تام:
```js
const quota = env.DB
  ? await checkAndConsumeMonthly(env, merchantId, "message")
      .catch((err) => { logError(err, { storeId: merchantId, context: "quota_check_failed" }); return { ok: true }; })
  : { ok: true };
```
يحتاج `logError` من `core/errorLog.js` (يُبنى/يُستكمل بالمسار أ).

**معيار القبول:** قرار موثّق من مالك المشروع (fail-open+تسجيل / fail-closed) قبل
أي تعديل على السطر — **لا أُغيّر سلوك التوفر بلا موافقة صريحة.**
