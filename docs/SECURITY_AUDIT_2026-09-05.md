**التاريخ:** 2026-09-05
**النطاق:** الكود الحي `hala-ai-os` (Cloudflare Pages Functions) + الواجهات الثابتة.
**المنهج:** ٤ فرق هجومية متوازية على ٤ أسطح (مصادقة/صلاحيات · حقن/SSRF/prompt-injection ·
سبام/استنزاف محفظة · ويبهوكس/أسرار/كريبتو). كل بند حرج **تُحقّق منه يدوياً بالكود** بعد

## الحرجة (CRITICAL) — استغلال فوري بلا مصادقة

### C1 — ويبهوك Zid: ريلاي رسائل واتساب مفتوح لأي رقم *(فريقان مستقلان)*
`functions/api/webhooks/zid.js:66-102` — يستقبل ويعالج **بلا أي تحقق توقيع، بلا سر، بلا حد
معدل**. السطر ٨٩ يكتب `signatureOk: true // Zid webhooks verified at network level` —
**ادعاء كاذب**، لا يوجد أي فحص شبكي. المسار عام على الإنتاج.

الاستغلال (طلب واحد):
```
POST https://halah.aura.sa/api/webhooks/zid
{"event":"abandoned_cart.created","cart":{"customer":{"mobile":"<أي رقم>","name":"<نص المهاجم>"},"total":"999","url":"https://evil/pay"}}
```
`zid.js:30` يرسل `sendWaText` لرقم يختاره المهاجم، بنص ورابط يختارهما، **من رقم واتساب أورا
الموثّق** (`env.WHATSAPP_TOKEN`). = تصيّد/سبام من علامة موثوقة لأي رقم سعودي لم يوافق.

**الأثر:** تكلفة كل رسالة + **انهيار تقييم جودة الرقم عند Meta وحظر الواتساب** (يسقط كل التجار)
+ تعبئة `webhook_log` بحمولة غير محدودة. يناقض تماماً الحارس الصحيح الموجود بـ`whatsapp/send.js:15`.

**الإصلاح:** تحقق HMAC على الـraw body قبل أي عمل (انسخ نمط `webhooks/salla.js:23`)، fail-closed
عند غياب `ZID_WEBHOOK_SECRET`، احذف `signatureOk: true`. **أو** احذف المسار كلياً — بقية تكامل
Zid أصلاً بـ`docs/archive/deprioritized-features/`.

### C2 — تجاوز الحصة: مفتاح الحصة سلسلة يختارها المهاجم → ذكاء اصطناعي مجاني بلا حد *(فريقان)*
`session.js:111-127`: بلا جلسة، `resolveStoreId` يرجع الـ`storeId` المُدّعى حرفياً طالما ما له
`accounts` row — **لا يُفحص أبداً مقابل جدول `merchants`**. و`chat.js:122` و`copy.js` يمرّرانه
مباشرة، و`meter.js:164` يبني مفتاح الحصة عليه. **وفوقها `/api/chat` و`/api/copy` بلا `checkRateLimit`
إطلاقاً** (تحقّقت: مو ضمن مستوردي الدالة).

الاستغلال: `POST /api/chat {"storeId":"x1"}`، `"x2"`… كل معرّف جديد = **حصة شهرية طازجة (٣٠٠
رسالة/٦٠ وصف)**. حلقة واحدة تستنزف كل سعة الذكاء المجانية للحساب كامل (Workers AI ثم Groq ثم
OpenRouter ثم DeepSeek). + صفوف `usage_quota` غير محدودة.

**الإصلاح:** اشترط وجود المعرّف بـ`merchants`؛ للمجهول اقصره على `default-store` الحرفي فقط.
قِس المجهول بمفتاح مشتق من IP لا باسم يختاره المتصل. أضف `checkRateLimit` لـ`chat` و`copy`.

### C3 — XSS مخزّن بلوحة الأدمن عبر `storeName` → سيطرة كاملة على واجهات الأدمن *(محقّق يدوياً)*
`signup.js:22` يأخذ `storeName` بـ`.slice(0,100)` فقط — **بلا `sanitizeInput`**. يُخزَّن، ثم
يُحقن **خاماً** بـ`innerHTML` عند `admin.html:659`: `${row?.storeName ?? 'متجر غير معنون'}`.
(نفس المشكلة باسم متجر Salla عبر `webhooks/salla.js:53`.)

الاستغلال: سجّل حساب باسم متجر = `<img src=x onerror=...>`. لمّا يفتح المالك `/admin`، الحمولة
تشتغل **بجلسة الأدمن نفس الأصل**. الكوكي `HttpOnly` (ما يُقرأ) لكنه يُرسَل تلقائياً، فتستدعي
الحمولة أي `/api/admin/*`: سحب كل الحسابات، سحب `consultation_bookings` (أسماء + أرقام عملاء =
PII حسّاس PDPL)، تعطيل/تفعيل حسابات التجار. والتسريب غير محجوب (راجع M5).

**الإصلاح:** اهرب عند المصدر (sink) — `textContent` أو دالة escape على كل `${...}` بـ
`admin.html:658-682` و`746-756`. دفاع بالعمق: `sanitizeInput(storeName,100)` بـ`signup.js`.

### C4 — تسرّب معرّف متجر سلة → استيلاء عابر للمستأجرين بلا مصادقة *(فريق المصادقة)*
`store/status.js:23-33`: بجسم فارغ وبلا كوكي، يرجع
`SELECT * FROM merchants WHERE created_at > datetime('now','-5 minutes') ORDER BY created_at DESC LIMIT 1`.
حارس العزل تحته (`:38-40`) يمنع فقط المتاجر اللي لها حساب — متاجر تثبيت سلة **ما لها حساب**،
فتمر ويُرجَع `storeId`.

سلسلة الاستغلال:
1. المهاجم يطقطق `POST /api/store/status` بجسم `{}` كل ٦٠ث → كل تثبيت سلة جديد يسلّم معرّفه.
2. `POST /api/store/overview {"storeId":"m_..."}` → منتجات المتجر الحية، **طلبات بأسماء عملاء**،
   سلات متروكة **بأرقام هواتف** (بتوكن OAuth المخزّن للتاجر).
3. `POST /api/store/publish` → يكتب نصاً عشوائياً على منتج المتجر الحي.
4. `POST /api/store/bulk/upload` → يحرق حصة التاجر · `POST /api/store/context` يسمّم تعليمات بوته.

**الإصلاح:** احذف fallback الـ٥ دقائق بـ`status.js` (خلّ الـonboarding يحمل المعرّف من الـredirect)،
واحذف الفرع المجهول من `resolveStoreId` — أنشئ جلسة حقيقية وقت التثبيت (مسار `salla_embedded`
يسويها صح أصلاً) واشترط `getSessionMerchantId()` لكل كتابة `/api/store/*`.
(ملاحظة: المعرّف أضعف من الموثّق — `m_ + randomUUID().slice(0,12)` ≈ ٤٤ بت لا ٩٦.)

## العالية (HIGH)

### H1 — CSRF على كل مسار يغيّر حالة *(فريقان)*
الكوكي `SameSite=None` (`session.js:88`) بلا أي فحص Origin/Referer ولا توكن CSRF، و`withApi`
يستدعي `request.json()` **بلا فحص Content-Type** (`respond.js:36`) — فطلب cross-site بـ
`Content-Type: text/plain` هو "simple request" بلا preflight، والكوكي يُرفق، والمعالج يشتغل.
أهداف: `store/context` (حقن prompt دائم)، `store/publish`، `bulk/upload`، وللأدمن `admin/accounts`
و`admin/aura_whatsapp` (استبدال توكن واتساب).
**الإصلاح:** ارفض POST/PUT/PATCH ما لم يبدأ `Content-Type` بـ`application/json` (يعيد حماية
preflight)، وأضف allowlist لـOrigin. أبقِ `SameSite=None` للـiframe.

### H2 — SSRF عبر `imageUrl` بلا allowlist ولا سقف ولا حد معدل *(محقّق)*
`gateway.js:293` — `fetch(imageUrl)` ثم `arrayBuffer()` بلا فحص مخطط/مضيف/redirect/حجم.
`copy.js` يمرره بـ`.slice(0,500)` فقط، والمسار مجهول (default-store) وبلا rate limit.
Workers ما توصل ١٦٩.٢٥٤/localhost/RFC1918 من الحافة، فالأثر الواقعي: **مزوّر طلبات/ماسح منافذ
مجهول** بعناوين Cloudflare + قراءة جزئية عبر وصف نموذج الرؤية + استنزاف ذاكرة (L4).
**الإصلاح:** `new URL`، اشترط https، ارفض IP literal/خاص، allowlist مضيفين، `redirect:'error'`،
`AbortSignal.timeout(5000)`، سقف بايتات، + `checkRateLimit`.

### H3 — XSS مخزّن بلوحة الأدمن عبر اسم عميل واتساب *(محقّق)*
مسار الواتساب لا ينقّي `contactName`/`msg.name` (`webhook.js:153,238`) → `admin.html:747` innerHTML.
المهاجم يضبط اسم واتسابه حمولة، يراسل رقم أورا، يحجز استشارة → تُنفَّذ بلوحة الأدمن. (حد طول
اسم واتساب ~٢٥ حرف يضيّقها لا يمنعها.)
**ملاحظة دقيقة:** `[BOOK_SLOT:x]` من مخرجات النموذج تُخزَّن بلا فحص مقابل `WEEKLY_SLOTS` — محقونة،
لكن يحجبها حالياً **عدم تطابق أسماء حقول** بالصدفة (`slot_label` مقابل `preferredSlotLabel`) لا
حارس مقصود؛ إعادة تسمية أي طرف تفتحها.
**الإصلاح:** اهرب عند الـsink + `sanitizeInput` على الاسم + تحقق `WEEKLY_SLOTS.includes()`.

### H4 — تخمين OTP إعادة كلمة المرور *(فريق المصادقة)*
`forgot_password.js:64` يكتب OTP قبل التسليم، ٦ أرقام (`:29`)، `reset_password.js` **بلا عداد
فشل لكل بريد ولا قفل** — الكابح الوحيد rate limit بالـIP، وهو يفشل مفتوحاً عند غياب KV.
**الإصلاح:** عدّاد فشل لكل بريد (أعد استخدام `login_attempts`)، إبطال بعد ٥ محاولات، رفع الرمز
لـ≥٨ من base32.

### H5 — تصعيد صلاحيات: تسجيل بريد أدمن غير مُطالَب به *(محقّق)*
`requireAdmin` يحدد الأدمن بمطابقة `accounts.email` مع `ADMIN_EMAILS` — لا عمود `is_admin`.
و`signup.js` **بلا تحقق بريد إطلاقاً**. لو بريد أدمن ما له `accounts` row بعد، المهاجم يسجّله أول
ويصير أدمن. الحاجز الجزئي: 409 على بريد مسجّل مسبقاً — يعتمد على أن كل بريد أدمن مسجّل سلفاً (مو
حارس مقصود).
**الإصلاح:** تحقق بريد قبل تفعيل الحساب، و/أو صلاحية أدمن عبر توفير صريح لا "من يملك row بهذا البريد".

### H6 — سكربتات طرف ثالث بلا نسخة ولا SRI على لوحة موثّقة *(فريق الويبهوكس)*
`dashboard.html:30` — `unpkg.com/@salla.sa/embedded-sdk/.../index.js` بلا نسخة ولا `integrity`؛
`cdn.tailwindcss.com` مثله. نشر npm مسموم يشتغل بأصل لوحة التاجر، ويستدعي `/api/*` بالكوكي تلقائياً،
والـCSP يوسّع `/dashboard` ليشمل unpkg بـ`connect-src` (قناة تسريب).
**الإصلاح:** ثبّت نسخة + `integrity` + `crossorigin`، أو استضف الحزم بـ`dist/` واحذف unpkg/tailwind
من CSP.

### H7 — نسب الحصة لـ`"hala"` (بلا قياس) من طلب مجهول
`meter.js:25,168` يعفي `"hala"`، و`session.js:126` قد يرجعه لمجهول. `POST /api/chat {"storeId":"hala"}`
= ذكاء بلا أي قياس (يعتمد على عدم وجود `accounts` row لـ`hala`).
**الإصلاح:** ارفض المعرّفات المحجوزة من مدخلات العميل.

### H8 — عدّادات KV غير ذرّية (سباق) بالميتر والليمتر *(فريق السبام)*
`meter.js:60-72` و`rateLimit.js:10-33`: get→compare→put بلا ذرّية، والـput غير مُنتظَر، وKV
eventually-consistent. مئات الطلبات المتوازية تمر. المسار البارد بـD1 ذرّي وصحيح لكن يُتجاوز دائماً
لمّا يكون KV مربوطاً.
**الإصلاح:** Durable Object، أو D1 كمرجع وKV كـcache يمنع فقط لا يمنح.

### H9 — واتساب: Whisper + Vision قبل بوابة الحصة/الطوفان
مسار الوسائط بالويبهوك ينفّذ التفريغ الصوتي والرؤية **قبل** `autoReply` (حيث الحصة والتصعيد).
مرسل مبرمج بمقاطع صوت/صور يحرق نيورونات + رسالة صادرة مدفوعة لكل رسالة. (التوقيع نفسه صحيح وأول.)
**الإصلاح:** token bucket لكل رقم بأعلى الحلقة قبل تنزيل/تفريغ الوسائط.

### H10 — قفل تسجيل يملأ مقاعد التجربة (DoS)
`signup.js:40` يطبّق سقف ٢٠ فعلاً، لكن **بلا rate limit ولا Turnstile ولا تحقق بريد** → ٢٠ POST
تملأ كل المقاعد بثانية، وكل تاجر حقيقي بعدها يصطدم بـ`TRIAL_FULL`، بلا مسار استرجاع.
**الإصلاح:** `checkRateLimit` + Turnstile إلزامي + تحقق بريد قبل احتساب المقعد.

## المتوسطة (MEDIUM)

- **M1 — استيلاء مسبق على حساب Google:** `google.js:62` يتبنّى `merchant_id` لبريد مسجّل. المهاجم
  يسجّل `victim@gmail` بباسورده أولاً؛ لمّا يدخل الضحية بـGoogle يقع بحساب المهاجم. *الإصلاح:* اطلب
  الباسورد المحلي أو فرض reset عند الربط.
- **M2 — لا إبطال للجلسات:** توكن HMAC عديم الحالة ٣٠ يوم بلا `jti`/إصدار. تعطيل الحساب أو reset
  الباسورد ما يقتل الجلسة. *الإصلاح:* عمود `session_version` بالحمولة الموقّعة.
- **M3 — قفل تسجيل الدخول لكل بريد (DoS موجّه):** `db.js:579` يقفل بالبريد لا (IP+بريد). ٥ محاولات
  فاشلة تقفل أي تاجر معروف. *الإصلاح:* اقفل بأزواج (بريد،IP) + تأخير أسّي.
- **M4 — علامات تحكم النموذج تُنفَّذ كأوامر موثوقة (حقن prompt):** `webhook.js:140-156` يعامل
  `[ESCALATE]`/`[OFFER_SLOTS]`/`[BOOK_SLOT:x]` كقناة أوامر، ورسائل العميل تُدمَج بلا فواصل، بلا
  بوابة مخرجات. حقن يسرّب النظام أو تعليمات/RAG تاجر آخر. *الإصلاح:* تحقق كل علامة مقابل مجموعة
  مغلقة، غلّف رسائل العميل بفواصل "بيانات لا أوامر"، بوابة مخرجات قبل `sendWaText`.
- **M5 — CSP: `'unsafe-inline'` + بروكسيات CORS مفتوحة بـ`connect-src`** *(فريقان)*: `_headers:6`
  يسمح `api.allorigins.win` و`corsproxy.io` — أي XSS يسرّب عبرهما ضمن السياسة. *الإصلاح:* احذفهما،
  اتجه لـnonce.
- **M6 — الخادم يولّد كود خصم ١٠٪ حقيقي على `isBuyIntent` من النموذج:** `chat.js:206-212` يبني
  `HALA-<name>-10` لمّا يقرر النموذج نية شراء — يناقض قاعدة الصدق و`persona.js:62` (ممنوع اختراع
  كود خصم). *الإصلاح:* كوبون فقط من حملة يفعّلها التاجر صراحة، مخزّن ومنتهي ولمرة واحدة.
- **M7 — أسرار حية بـ`.dev.vars` بشجرة العمل** *(فريق الويبهوكس)*: توكن Meta ومفتاح OpenRouter
  حقيقيان. **مؤكَّد: غير مُودَعين بـGit أبداً** (`.gitignore` + `git log -S` نظيف) ولا يتسربان لـ
  `dist/`. لكن مجلد `Downloads/` خزنة سيئة. *الإصلاح:* دوّر المفتاحين لو المجلد شورك/زُووِد يوماً.
- **M8 — سر افتراضي مكتوب بالكود** `aura_whatsapp.js:52`: `env.WHATSAPP_VERIFY_TOKEN || "hala-verify-secret"`
  يناقض قاعدة fail-closed بـ`CLAUDE.md`. *الإصلاح:* ارمِ خطأ عند الغياب. (وراجع `|| "9665..."` كأرقام
  واتساب افتراضية حقيقية بـ`support.js`/`chat.js`/الكرون.)
- **M9 — ويبهوك سلة بلا حماية إعادة/idempotency:** التوقيع صحيح على raw body وconstant-time
  وfail-closed، لكن لا نافذة زمنية ولا nonce. إعادة `app.store.authorize` تُعيد `saveTokens` (رجوع
  توكن لقيمة قديمة). *الإصلاح:* خزّن توقيع الحدث بـKV بـTTL ٢٤س وارفض المكرر.
- **M10 — Turnstile اختياري من العميل ويفشل مفتوحاً:** `support.js:33`/`login.js:25` يتحققان فقط لو
  التوكن موجود، و`security.js:9` يرجع `{success:true,bypass:true}` عند غياب المفتاح. *الإصلاح:*
  اشترط التوكن + fail-closed.

## المنخفضة (LOW)

- **L1** — `default-store` مستأجر مجهول مشترك قابل للكتابة (حقن prompt مخزّن بالديمو العام) — `session.js:113`.
- **L2** — `X-Forwarded-For` مقبول كـIP احتياطي (تقسيم دلاء الليمتر) — عدة ملفات؛ `image.js` يسويها صح.
- **L3** — `CRON_SECRET` وقارن `hub.verify_token` بـ`!==`/`===` لا constant-time (fail-closed صحيح، الأثر عملي منخفض).
- **L4** — جسم JSON غير محدود + `arrayBuffer()` غير محدود → OOM للـisolate — `respond.js:35`, `gateway.js:296`.
- **L5** — self-XSS بقائمة فشل الدفعة `dashboard.html:633` (نفس المستأجر؛ حقيقي فقط عند استيراد CSV طرف ثالث).
- **L6** — لا HSTS على `halah.aura.sa` (نطاق `.dev` محمي بالـpreload، المخصص لا) — `_headers`.
- **L7** — كتابة D1 غير مصدّقة عبر `GET /api/webhooks/salla?code=x` (تسميم سجل/استنزاف تخزين رخيص) — `salla.js:108`.

## ما تحقّقنا أنه **سليم** (حراس موجودة فعلاً — لا تُلمس)

- توكن الجلسة: HMAC-SHA256، timing-safe، fail-closed على `SESSION_SECRET`، لا اشتقاق احتياطي. غير قابل للتزوير.
- توقيع ويبهوك سلة + Meta: على raw body، constant-time، fail-closed، **قبل** أي parse/عمل.
- Google ID token: مُتحقَّق عبر tokeninfo، `aud` مثبّت، `email_verified` مطلوب.
- Salla embedded: introspection عبر `api.salla.dev`، `S-Source` مثبّت، fail-closed.
- AES-GCM: IV عشوائي طازج كل تشفير، `importKey` يرمي عند غياب المفتاح.
- OAuth state: nonce ١٢٨ بت، HMAC، TTL ١٠د، مُتحقَّق فعلاً بالـcallback، يُحرَق مرة واحدة. لا CSRF على OAuth.
- **لا حقن SQL:** كل الاستعلامات `.bind()` (٤٠+ موقع خارج db.js راجَعناها). لا interpolation داخل `prepare()`.
- كل مسارات `admin/*` + `/api/image` تستدعي `requireAdmin`.
- عزل ملكية دفعات B3 (`getBulkJob` يفلتر بـ`merchant_id`) — لا قراءة عابرة.
- resolveStoreId للمسجّلين: الجلسة تغلب المعرّف المُدّعى — مستأجر مسجّل لا يقدر يتنقّل.
- لا تسريب أسرار/PII بالـlogs.
