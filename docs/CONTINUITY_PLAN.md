## ٢. الأسرار — أين تُدار، لا قيمتها

من `AGENT.md` §١٠. القيم نفسها بخزنة Cloudflare فقط:

| السر | الأمر لعرضه/تحديثه | ملاحظة |
|---|---|---|
| `SESSION_SECRET` | `npx wrangler pages secret put SESSION_SECRET --project-name hala-ai-os` | تغييره يُسقط كل الجلسات الحية فوراً |
| `ENCRYPTION_KEY` | نفس النمط | تغييره يُفقد الوصول لأي بيانات مشفَّرة قديمة — **لا يُغيَّر إلا بخطة هجرة** |
| `ADMIN_EMAILS` | نفس النمط | قائمة إيميلات مفصولة بفواصل — هذا **العمود الوحيد** لصلاحية الأدمن (لا عمود DB عمداً) |
| `SALLA_APP_ID` / `CLIENT_ID` / `CLIENT_SECRET` / `WEBHOOK_SECRET` | نفس النمط | من لوحة شركاء سلة |
| `WHATSAPP_TOKEN` / `PHONE_ID` / `VERIFY_TOKEN` / `APP_SECRET` | نفس النمط | التوكن الحالي مؤقت حتى يُستبدل بـSystem User دائم (د.١) |
| `TURNSTILE_SECRET_KEY` | نفس النمط | اختياري — النظام يعمل بلا مفتاح لكن يمرّر الكل |
| `GROQ_API_KEY` / `OPENROUTER_API_KEY` / `DEEPSEEK_API_KEY` / `HF_TOKEN` | نفس النمط | اختيارية — تعاقب `gateway.js` يتخطاها إن غابت |

**قاعدة تدوير الطوارئ (سر تسرّب أو حساب اختُرق):**
1. `npx wrangler pages secret put <NAME> --project-name hala-ai-os` بقيمة جديدة فوراً
2. `npm run deploy` — الأسرار الجديدة تُفعَّل **فقط بعد نشرة جديدة** (درس موثّق من B4، لا تفترض التفعيل الفوري)
3. تحقق حي: `/api/health` = 200

## ٤. إجراء الطوارئ عند عطل وأنت غير متاح

بالترتيب، بلا حاجة لفهم الكود:

1. **تحقق حالة النظام:**
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" https://hala-ai-os.pages.dev/api/health
   ```
   `200` = النظام حي، المشكلة بمكان آخر (توكن منتهٍ غالباً). غير `200` = انظر ٢.

2. **راجع آخر نشرة:**
   ```bash
   npx wrangler pages deployment list --project-name hala-ai-os | grep Production
   ```
   لو آخر نشرة فاشلة أو قديمة جداً، أعد النشر من آخر نسخة معروفة تعمل:
   ```bash
   npm run deploy
   ```

3. **لو البوت لا يرد على واتساب تحديداً:** التوكن غالباً منتهٍ (التوكن المؤقت
   ينتهي كل ~ساعة إلى أن يُستبدل بدائم — راجع د.١). يحتاج شخص عنده دخول Meta
   Business Manager يولّد توكناً جديداً ويحدّثه بنفس أمر §٢.

4. **لو قاعدة البيانات تبدو تالفة أو بيانات مفقودة:** **لا تُصلح يدوياً.** استعد
   من آخر نسخة احتياطية:
   ```bash
   ls backups/
   npx wrangler d1 execute halah-tr-db --remote --file="backups/<آخر ملف>.sql"
   ```
   ⚠️ هذا يكتب فوق البيانات الحية — استخدمه فقط عند تأكد أن الحالي تالف أسوأ من فقدان آخر ساعات.

5. **لا حل من الأربعة أعلاه؟** التصعيد لمن يملك دخول Cloudflare (§١) لمراجعة
   سجلات Workers مباشرة من لوحة Cloudflare.

## ٥. نسخة احتياطية — الروتين

```bash
npm run backup              # نسخة كاملة، أسبوعياً على الأقل
npm run backup -- --schema-only   # مخطط فقط، قبل أي هجرة
```

النسخ بمجلد `backups/` (مستثنى من git — تحتوي بيانات عملاء حقيقية). يُحتفظ
بآخر ١٤ نسخة تلقائياً.

**قبل أي `wrangler d1 migrations apply --remote`: نسخة أولاً، بلا استثناء.**
