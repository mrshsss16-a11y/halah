## لماذا أربعة مسارات لشخص واحد؟

التوازي الحقيقي عندنا **ليس أربعة مطوّرين** — بل أربعة أنواع وقت مختلفة تمشي معاً:

| المسار | نوع الوقت | من يملكه |
|---|---|---|
| **أ — الأساس** (عزل · أمن · معيارية) | بناء + مراجعة مستمرة | الوكيل، بإشرافك |
| **ب — هالة** (القنوات والمحتوى) | بناء | الوكيل |
| **ج — منصة أورا** (اللوحة والتقارير والمراجعة) | بناء | الوكيل |
| **د — الخارج** (اعتمادات · قرارات · تشغيل) | **انتظار + قرار** | **أنت** |

المسار **د** لا يستهلك ساعة برمجة واحدة، لكنه يحدد سقف الثلاثة الأخرى. تقديمه أولاً
هو أكبر تسريع ممكن.

**قاعدة الأسبقية:** لا يُقبل أي عمل في **ب** أو **ج** إن كسر معياراً من **أ**.
الأساس ليس مرحلة تنتهي — بل بوابة قبول دائمة.

# المسار أ — الأساس: العزل والأمن والمعيارية

> هذا المسار هو الفرق بين منتج يعيش سنتين ومنتج ينهار عند أول عميلين يتشاركان الخطأ.

## أ.١ معيار عزل العملاء (Multi-Tenancy) — إلزامي على كل سطر

**المبدأ:** هوية العميل (`storeId` / `merchantId`) تُشتق **من الجلسة الموقّعة فقط**،
ولا تُقرأ أبداً من جسم الطلب أو الاستعلام أو الترويسة. ما يدّعيه العميل عن هويته
ليس دليلاً.

| الطبقة | القاعدة | الحالة |
|---|---|---|
| **الهوية** | `resolveStoreId(request, env)` المصدر الوحيد. الجلسة تتغلب على أي `storeId` مُرسل | ✅ `core/session.js` |
| **D1** | كل استعلام على جدول فيه بيانات عميل **يجب** أن يحمل `WHERE merchant_id = ?` — لا استثناء، حتى في `SELECT COUNT` | 🟡 يُدقَّق جدولاً جدولاً (أ.١.ت) |
| **KV (الكاش)** | كل مفتاح يبدأ بـ`storeId:` — كاش رد عميل لا يصل لعميل آخر (تسريب P0 أُغلق `250e54d`) | ✅ `buildCacheKey()` |
| **Vectorize (الذاكرة)** | كل استعلام مقيّد بـ`filter: { storeId }`. لا بحث بلا فلتر | ✅ metadata `storeId` |
| **السجلات** | كل سطر سجل يحمل `storeId` + `requestId` — بلا PII (لا جوال، لا إيميل، لا نص رسالة) | ⬜ يُبنى مع معرّف الطلب |
| **الأدمن** | قراءة عابرة للعملاء **فقط** عبر `requireAdmin` (يتحقق من `ADMIN_EMAILS` كسرّ بيئة — لا عمود `is_admin` عمداً) + سطر تدقيق: من، متى، أي عميل | 🟡 `requireAdmin` ✅ · التدقيق ⬜ |
| **الملفات/الصور** | كل مسار تخزين يبدأ بـ`storeId/` | ✅ `store_logos` |
| **الحصص** | العدّاد لكل `storeId` — استنفاد عميل لا يمسّ آخر | ✅ `meter.js` |

**أ.١.ث — فجوة الريبليكا (Replication Gap):** D1 يخدم القراءات من نسخ متأخرة عن
الأساسية. أي مسار **يكتب ثم يقرأ فوراً** (مثال: بعد `app.store.authorize` — التاجر
يُربط ثم يُقرأ سجله مباشرة) قد يرجع ٤٠٤ خادعاً. القاعدة: القراءة الفورية بعد كتابة
حرجة تستخدم علم `primary`، وتتنازل عن سرعة الحافة عمداً. نفس فئة أعطال B4 الموثّقة
بـ`ROADMAP.md` — عرض مضلل، سبب مختلف.

**أ.١.ت — تدقيق العزل (يوم واحد، الأسبوع ٢):** سكربت يمرّ على كل استعلام D1 في
`functions/` ويرفض أي استعلام يلمس جدولاً فيه `merchant_id` بلا شرط عليه. يُضاف
لـ`npm test`. **هذا يحوّل العزل من "انتباه المطوّر" إلى "فحص آلي"** — الفرق الحاسم
لمطوّر واحد.

## أ.٣ المعيارية (Modular Monolith) — عقود ثابتة

**الطبقات وحدودها:**

```
api/            نقاط دخول — تنسّق فقط. ممنوع: منطق أعمال، استعلام DB مباشر، بناء prompt
_lib/core/      حوكمة — جلسة · هوية · حصص · معدل · رد · أمن · db
_lib/ai/        النواة الذكية — persona (مصدر واحد) · gateway (تعاقب المزودين) · memory · intents
_lib/integrations/  محوّلات — كل تبعية خارجية خلف ملف واحد بعقد موحّد
_lib/services/  ⬜ جديد — منطق الأعمال (وصف، تقرير، استرداد) يُستدعى من api/ ومن cron/ معاً
```

**عقد المحوّل** (كل قناة/منصة تحققه بالحرف — إضافة قناة = ملف واحد، صفر تعديل نواة):

```js
export function isConfigured(env)             // الأسرار موجودة؟ (لا تُرمى هنا — تُرمى عند الاستخدام)
export async function receive(request, env)   // تحقق التوقيع → { storeId, from, text, meta }
export async function send(env, to, payload)  // إرسال — يرمي خطأ مصنّفاً عند الفشل
export async function fetchContext(env, id)   // بيانات المصدر (اختياري)
```

**قواعد لا تُكسر:**

| # | القاعدة | لماذا |
|---|---|---|
| M1 | `api/*` تنسّق فقط — تستدعي `services/` وترجع `json()` | نقطة الدخول تتغير مع القناة، المنطق لا |
| M2 | الشخصية مصدر واحد `ai/persona.js` — كل قناة تستوردها | نسختان = لهجتان تتباعدان، واللهجة هي الخندق |
| M3 | تبعية خارجية = محوّل واحد بعقد واحد | تغيّر API خارجي = ملف واحد يتعدّل |
| M4 | لا حالة عامة بين الطلبات (Workers لا يضمنها) | مصدر أعطال صامتة |
| M5 | خطأ مصنّف: `{ code, userMessage(ar), internal }` — العميل يرى العربي، السجل يرى الداخلي | صفر `429` خام للتاجر، وتشخيص كامل لك |
| M6 | كل وحدة لها اختبار منطق واحد على الأقل يفشل لو كُسر العزل أو التوقيع أو الحصة | الاختبار الحالي يتحقق من التصدير فقط |
| M7 | هجرة D1 = ملف مرقّم + `npm run backup` قبلها + تطبيق `--remote` موثّق | لا تعديل مخطط يدوي |
