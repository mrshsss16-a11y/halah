# 🤖 تنظيم الوكلاء — تزامن مترابط بلا تدهور جودة

> **المشكلة التي تحلّها هذه الوثيقة:** وكلاء متعددون يعملون بالتوازي على مستودع واحد
> **يرفعون السرعة ويخفضون الجودة** ما لم تُرسم الحدود مسبقاً. هذا ليس افتراضاً —
> حدث فعلياً في هذا المشروع يوم 2026-09-06 (§٠ أدناه).
>
> كُتبت 2026-09-06 · تكمّل `PARALLEL_TRACKS.md` (ماذا يُبنى) بـ**من يبنيه، وأين
> بالضبط، وبأي ترتيب**.

## ٠. الأدلة — خمسة أعطال حقيقية من جلسة واحدة

كل قاعدة في هذه الوثيقة مشتقة من عطل وقع فعلاً، لا من قلق نظري:

| # | ما حدث | الجذر | القاعدة المشتقة |
|---|---|---|---|
| ١ | وكيل أضاف `[observability]` لـ`wrangler.toml` → **`npm run deploy` فشل كلياً** (حقل Workers، والمشروع Pages) | وكيل طبّق "أفضل ممارسة" عامة بلا التحقق من نوع المشروع | **م١:** ملفات النشر مالك واحد فقط |
| ٢ | وكيلان عدّلا `backup-db.mjs` عكسياً (`npx.cmd` ↔ `shell:true`) | ملكية مشتركة بلا تنسيق | **م٢:** ملكية حصرية لكل مسار |
| ٣ | `PARALLEL_TRACKS.md` تغيّر ٣ مرات أثناء قراءته | وثيقة حاكمة يكتب فيها الجميع | **م٣:** الوثائق الحاكمة تُحدَّث بمرحلة مخصصة |
| ٤ | `errorLog.js` تعليقه "console فقط" بينما مصرف D1 مبني | تحديث الكود بلا تحديث وصفه | **م٤:** الوصف الذاتي جزء من "منجز" |
| ٥ | `audit-isolation.mjs` يطبع "صفر مخالفة" وهو أعمى عن استعلامات المتغيّرات | أداة تحقق بلا تحقق من حدودها | **م٥:** كل أداة فحص توثّق ما لا تراه |

**الاستنتاج:** الخطر ليس التوازي — بل **الحالة المشتركة القابلة للتعديل بلا مالك**.

## ١. المبادئ الخمسة الحاكمة

| # | المبدأ | التطبيق العملي |
|---|---|---|
| **م١** | **ملفات النشر مقدّسة** | `wrangler.toml` · `package.json` · `scripts/*.mjs` · `_headers` → **وكيل البنية وحده**. أي وكيل آخر يقترح تعديلاً كنص، لا يكتبه |
| **م٢** | **ملكية حصرية للمسارات** | كل مسار في المستودع له **مالك واحد** في أي مرحلة. لا كتابة متقاطعة إطلاقاً |
| **م٣** | **الوثائق الحاكمة تُجمَّد أثناء المرحلة** | `PARALLEL_TRACKS.md` · `AGENT.md` · هذه الوثيقة → تُحدَّث **فقط** في بوابة نهاية المرحلة، بيد وكيل التوثيق |
| **م٤** | **الوصف الذاتي جزء من التسليم** | تعليق الملف يصف حالته الحالية. تعليق بائت = مهمة غير منجزة، لا "تفصيل تجميلي" |
| **م٥** | **كل أداة فحص توثّق عماها** | "صفر مخالفة" بلا بيان الحدود = ثقة زائفة، أخطر من عدم وجود الأداة |

## ٢. طاقم الوكلاء — ستة أدوار، لا تتداخل

| الوكيل | يملك (يكتب) | يقرأ فقط | ممنوع منعاً باتاً |
|---|---|---|---|
| **🏗️ البنية** (Infra) | `wrangler.toml` · `package.json` · `scripts/` · `_headers` · `migrations/` | كل شيء | منطق الأعمال · محتوى الشخصية |
| **🔐 الأمن والعزل** (Security) | `functions/_lib/core/` (session · auth · meter · rateLimit · security) | كل شيء | `api/*` · `ai/persona.js` · ملفات النشر |
| **🧠 النواة الذكية** (AI Core) | `functions/_lib/ai/` (persona · gateway · memory · intents) | `core/` · `integrations/` | `core/` · قواعد الحصص · ملفات النشر |
| **🔌 المحوّلات** (Adapters) | `functions/_lib/integrations/` (salla · zid · whatsapp · instagram) | `core/` · `ai/` | `ai/persona.js` · `core/` · ملفات النشر |
| **🖥️ الواجهة** (Surface) | `functions/api/` · `*.html` · `partials/` | كل شيء | `_lib/**` · ملفات النشر |
| **🔍 المدقّق** (Auditor) | **لا يكتب كوداً إطلاقاً** — يكتب `docs/PROBLEMS.md` فقط | كل شيء | كل الكود. يبلّغ، لا يصلح |

**قاعدة الطاقم:** وكيل يحتاج تعديلاً خارج ملكيته → **يكتب طلباً في `PROBLEMS.md`**، ولا
يلمس الملف. المالك ينفّذه في مرحلته. هذا يمنع أعطال ١ و٢ بالكامل.

**المدقّق منفصل عمداً:** من يبني لا يستطيع الحكم على بنائه بحياد — وهذا مصدر العطل ٥.

## ٣. المراحل — تسلسل صارم، توازٍ داخل المرحلة فقط

```
مرحلة ٠ ──► مرحلة ١ ──► مرحلة ٢ ──► مرحلة ٣ ──► مرحلة ٤
(تسلسلي)   (وكيلان)    (٣ وكلاء)   (وكيلان)    (تسلسلي)
   │           │           │           │           │
   └── بوابة ──┴── بوابة ──┴── بوابة ──┴── بوابة ──┘
```

**لا وكيل يبدأ مرحلة قبل اجتياز بوابة المرحلة السابقة.** البوابة ليست اجتماعاً — بل
أمر يُشغَّل ونتيجته صفر أو واحد.

### 🔹 المرحلة ٠ — تثبيت الأرض (تسلسلي، وكيل واحد)

**الوكيل:** البنية وحده. لا توازٍ إطلاقاً.

| المهمة | لماذا هنا |
|---|---|
| تجميد `wrangler.toml` + توثيق ما لا يُضاف (تعليق `[observability]` موجود ✅) | يمنع تكرار العطل ١ |
| `npm run deploy` يتضمن اختبار الدخان آلياً (D6) | لا نشر يعتمد على تذكّر بشري |
| فهرس الملكية: ملف `.agent-ownership` يذكر مالك كل مسار | يمنع العطل ٢ آلياً |

**🚪 بوابة الخروج:**
```bash
npm test && npm run deploy   # يجب أن ينجح كلياً، بما فيه اختبار الدخان
```
**فشل = لا مرحلة ١.** أرض غير مستقرة تُضاعف كل عطل بعدها.

## ٤. عقد التسليم بين الوكلاء

أي وكيل ينهي مهمة يكتب في `PROBLEMS.md`:

```markdown
### [تم] <المهمة> — <الوكيل> — <التاريخ>
- **الملفات المعدَّلة:** (قائمة كاملة — لا "وغيرها")
- **ما تحقق حياً:** الأمر المُشغَّل + مخرجه الفعلي
- **ما لم يُختبر:** صريحاً — "لم أتحقق من X" أصدق من الصمت
- **طلبات لمالكين آخرين:** ملف + سبب + من يملكه
- **أوصاف ذاتية حُدِّثت:** (م٤)
```

**"ما لم يُختبر" حقل إلزامي.** كل الأعطال الخمسة أعلاه مرّت لأن أحداً افترض ولم يتحقق.

## ٥. قواعد التزامن — ما يمنع التصادم عملياً

| الحالة | القاعدة |
|---|---|
| وكيلان يحتاجان نفس الملف | **يتسلسلان.** لا استثناء. التوازي على ملف واحد = خسارة صافية |
| وكيل يحتاج تعديلاً خارج ملكيته | طلب في `PROBLEMS.md` → المالك ينفّذ |
| وثيقة حاكمة تحتاج تحديثاً | ينتظر المرحلة ٤ (م٣) |
| وكيل يقترح "أفضل ممارسة" عامة | **يتحقق من انطباقها على Pages تحديداً** قبل الكتابة (العطل ١) |
| أداة فحص جديدة | توثّق ما لا تراه، وإلا لا تُدمج (م٥) |
| تعارض بين وكيلين | المدقّق يحسم — لأنه لا يبني، فلا مصلحة له |

## ٦. لماذا هذا لا يبطئ العمل

الاعتراض المتوقّع: "ست أدوار وبوابات = بطء". الحساب الفعلي:

| البند | التكلفة |
|---|---|
| كتابة عقد تسليم | ٥ دقائق |
| بوابة مرحلة (`npm test` + دخان) | دقيقتان |
| **مقابل:** تشخيص `[observability]` الذي كسر النشر | **٤٥ دقيقة** في هذه الجلسة |
| **مقابل:** لو نُشر ولم يُكتشف | **٥٦ endpoint ساقط على الإنتاج** |

**البوابات أرخص من عطل واحد.** وهذا بمطوّر واحد يراجع؛ بلا مراجع بشري ثانٍ، البوابة
الآلية هي المراجع الوحيد.
