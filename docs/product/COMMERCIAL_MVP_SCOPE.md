# نطاق هالة التجاري: النسخة الأولى القابلة للبيع

**البيئة المستهدفة الآن:** `development` محلي ومعزول. لا تتصل هذه الخطة بموارد Cloudflare أو سلة أو واتساب أو Google الحية.

## قرار المنتج

هالة ليست CRM عاماً ولا بوتاً مفتوحاً. النسخة الأولى هي لوحة تحكم عربية للتاجر تساعده على تفعيل متجره، مراجعة جودة بيانات منتجاته وصوره، إنشاء drafts لأوصاف منظمة، وإدارة استرداد سلات محكوم من قبل السياسة. تبيع هالة **نتيجة قابلة للتفسير وتفعيل منضبط**، وليس «رسائل أكثر» أو «نصوص عشوائية» فقط.

## المستخدمون

| الدور        | ما يستطيع فعله                                                                                | ما لا يستطيع فعله                                |
| ------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| مالك المنظمة | إنشاء المنظمة، دعوة الفريق لاحقاً، ربط المتجر، اعتماد السياسات، مراجعة exports، إيقاف الخدمة. | تجاوز consent أو نشر محتوى غير معتمد تلقائياً.   |
| مشغل متجر    | استيراد منتجات وصور، مراجعة drafts، تشغيل preview، رؤية الحالات والتكاليف.                    | إدارة الأعضاء أو مفاتيح التكامل أو حدود المؤسسة. |
| مراجع محتوى  | مراجعة وصف/صورة واعتماد أو إرجاع draft مع سبب.                                                | تغيير OAuth أو policy تشغيلية.                   |
| دعم هالة     | يرى سجلات تدقيق مقيدة وطلبات تصعيد فقط.                                                       | لا يرى أسراراً أو محتوى متجر خارج تفويضه.        |

## رحلة التاجر

```text
صفحة هالة العامة
  → إنشاء حساب / دخول
  → إنشاء مساحة متجر
  → اختيار الخدمة المطلوبة
  → ربط سلة (development mock ثم OAuth staging)
  → استيراد منتجات / صور
  → مراجعة facts وdrafts
  → preview
  → طلب تفعيل الخدمة
  → لوحة الحالات والتكلفة والتصعيد
```

## صفحات النسخة التجارية

| الصفحة              | الغرض                                                                 | حالة النسخة الأولى                                              |
| ------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------- |
| `/`                 | تعريف عملي بهالة وCTA للتسجيل/الاستشارة.                              | تبنى الآن.                                                      |
| `/login` و`/signup` | هوية المستخدم وجلسة آمنة.                                             | تبنى عقودها وواجهتها؛ مزود البريد/Google الحي مؤجل حتى staging. |
| `/onboarding`       | إنشاء منظمة، اختيار هدف: محتوى منتجات أو استرداد سلات، وبدء ربط متجر. | تبنى الآن مع بيانات تطوير تركيبية.                              |
| `/app`              | ملخص الجاهزية والتنبيهات وCTA التالي.                                 | تبنى الآن.                                                      |
| `/app/products`     | استيراد، facts، صور، drafts، مراجعة وpreview.                         | واجهة ونماذج محلية الآن؛ LLM وadapter لاحقاً.                   |
| `/app/recovery`     | حالات السلات، policy/consent، budget، ومفتاح إيقاف.                   | UI + state fixtures الآن؛ webhook/WhatsApp لاحقاً.              |
| `/app/connections`  | سلة/زد/واتساب وحالة الربط من دون أسرار.                               | Salla mock فقط الآن؛ زد مؤجل.                                   |
| `/app/activation`   | طلب تفعيل واستشارة وخطة خدمة، بلا أسعار رقمية.                        | تبنى الآن.                                                      |
| `/app/audit`        | سجلات قرارات وexports وتصعيدات.                                       | read-only fixture ثم D1.                                        |

## ما نبنيه الآن

1. واجهة عربية RTL كاملة، بوابة دخول، لوحة تاجر، حراسة مسارات، وعقود منظمة.
2. core D1 محلي: organization، users، memberships، store connections، audit log، activation requests.
3. ميزة منتجات draft-first: فحص حقائق وصور وpreview محلي من دون اتصال متجر.
4. استرداد draft-first: آلة الحالات والسياسات والميزانية، من دون webhook أو إرسال حي.
5. صفحات تفعيل الخدمة والاستشارة، لا بوابة دفع أو سعر رقمي.
6. CI، اختبار وحدة وتكامل وE2E وaccessibility/RTL.

## ما لا نبنيه الآن

- لا تحصيل دفع أو اشتراك آلي قبل اختيار مزود مدفوعات ومتطلبات ضريبية وعقود تشغيل.
- لا Google OAuth أو إرسال بريد أو reset password حي قبل مزود identity/transactional email في staging.
- لا سلة OAuth أو webhook أو WhatsApp send أو زد production في development.
- لا توليد صورة أو تعديل صورة؛ الرؤية تحليل وflags فقط.
- لا مستخدمو عملاء المتجر أو بياناتهم الحقيقية في الاختبار.

## تعريف جاهزية البيع

لا نقول «جاهز للبيع» بسبب وجود صفحة دخول فقط. الجاهزية الأولى تعني: يستطيع تاجر إنشاء حساب وspace في staging، يمر onboarding، يرفع 20 SKU/صورة، يرى فحوصاً وdrafts وتوضيحات، يطلب تفعيل الخدمة، ويوجد سجل تدقيق ووسيلة تعطيل. ربط سلة وواتساب الحي يصبح بوابة منفصلة بعد اختبارات demo وموافقة صريحة.
