# Hala AI OS

هالة منصة استرداد سلات متروكة محكومة للمتاجر السعودية. هذا المستودع يحتوي على **المصدر الجديد القابل للصيانة** الذي يعاد بناؤه تدريجياً، وعلى لقطة واجهة عامة مرجعية فقط. لا يمثل هذا المستودع تطبيقاً إنتاجياً مكتملًا بعد.

> **قاعدة المنتج:** هالة لا ترسل رسالة لمجرد وجود سلة. تتحقق من سياسة المتجر الفعالة والموافقة وحالة السلة والمنع والميزانية، ثم تسجل سبب قرار الإرسال أو المنع وتكلفة التسليم.

## حالة التنفيذ

المرحلة الحالية هي `development` محلية ومعزولة. لا توجد في هذا المصدر أسرار أو رموز OAuth أو ربط Cloudflare أو متجر سلة/زد حقيقي أو قناة WhatsApp حية. لا يملك أي script أمراً للنشر الإنتاجي.

| المسار                | المسؤولية                                                              |
| --------------------- | ---------------------------------------------------------------------- |
| `apps/hala-edge/`     | تطبيق Hala edge: HTTP، modules، adapters، workflows وواجهة RTL لاحقاً. |
| `packages/contracts/` | عقود Zod وأنواع مشتركة للـHTTP والـwebhooks والحالات.                  |
| `packages/test-kit/`  | fixtures وbuilders تركيبية للاختبارات فقط.                             |
| `recovery/`           | لقطة Cloudflare العامة المؤرشفة؛ مرجع بصري وليست مصدراً للخادم.        |
| `docs/`               | قرارات معمارية وتشغيلية وهندسية.                                       |

## مبادئ التصميم

يستخدم هالة **modular monolith**: التطبيق واحد في البداية، لكن منطق المنتج مفصول عن HTTP وCloudflare وقواعد البيانات ومزودي سلة/زد وواتساب. تحفظ `modules/` قواعد الاسترداد والسياسات والتكلفة بلا SQL أو `fetch` أو bindings. توضع تفاصيل D1 وKV وSalla وZid وWhatsApp في `adapters/` خلف interfaces واضحة.

D1 هو مصدر الحقيقة. KV يستخدم للـcache والـrate limits فقط، وVectorize يعيد مرشحي معرفة فقط؛ تتحقق D1 من أن مصدر السياسة فعال قبل أي إجابة أو قرار. كل بيانات المتجر تحمل `organization_id` ويجب أن تختبر حدود العزل.

## بدء التطوير المحلي

يتطلب المشروع Node.js 22+ وpnpm. بعد نسخ `.dev.vars.example` إلى `.dev.vars` بقيم محلية وهمية فقط، استخدم الأوامر التالية:

```bash
pnpm install
pnpm typecheck
pnpm test
pnpm dev
```

يعمل `pnpm check` على التنسيق وlint وtypecheck والاختبارات. لا تستخدم بيانات عملاء أو أسرار أو حسابات إنتاج في fixtures أو logs أو بيئة development.

## الأمان والخصوصية

لا ترفع أسراراً إلى Git. افصل development وstaging وproduction بموارد وbindings وأسرار مستقلة. تحقق من webhook قبل parse، واحفظه في inbox idempotent، وعالج workflow خارج مسار الاستقبال. الاختبارات وRed Teaming تعتمد بيانات تركيبية وقنوات معزولة فقط.

لا تذكر مكتبة مبيعات هالة أسعاراً أو تكاليف رقمية، وتوجّه للاستشارة المجانية. أما لوحة تكلفة التاجر المحمية فتسجل تكلفة التسليم التشغيلية حسب بيانات مزود القناة فقط.

## اللقطة المستردة

توجد اللقطة العامة في [`recovery/public-cloudflare-snapshot/`](./recovery/public-cloudflare-snapshot/). لا تنشرها كما هي؛ لم يسترد منها منطق الخادم أو D1 أو KV أو Vectorize أو أسرار البيئة أو تكاملات سلة/واتساب.
